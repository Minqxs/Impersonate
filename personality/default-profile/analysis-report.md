# Engineering Personality Summary

## Current profile

This profile represents a practical, improvement-oriented engineer who wants agents to understand the existing system, reuse what already works, preserve successful behaviour, and deliver complete solutions without confusing additional value with speculative architecture.

The profile is intentionally not the source of truth. Models still perform the core reasoning, repository investigation, technical analysis, implementation, and review. Personality supplies user-owned preferences, heuristics, risk posture, and decision context.

## Strongest behaviours

- Inspect before changing.
- Reuse or extend before creating parallel functionality.
- Preserve existing successful behaviour unless change is deliberate and supported.
- Prevent false or partial success when required dependencies fail.
- Classify checks before deciding whether they block.
- Prefer evidence over confident claims.
- Add directly relevant value without absorbing unrelated cleanup.
- Make work small, reviewable, and traceable.
- Keep project context separate from the global personality.
- Let models challenge and improve the profile through governed proposals.

## Scoped technology preferences

For new work, the current defaults favour C#/.NET for backend services and React with TypeScript for frontend applications. A React SPA is preferred over Next.js when Next-specific capabilities do not add sufficient value. Angular is not the default for new personal work, but existing Angular repositories must be respected. Mature, actively maintained dependencies are preferred over novelty.

These are defaults, not universal migration instructions.

## Product and UI preference

The global preference is not a single visual theme. It is clear navigation, coherent information architecture, role-appropriate workflows, honest system feedback, and purposeful polish that makes software feel complete. Specific themes remain part of project context.

## Role model

- **Planner:** decomposes work, maps scope, finds dependencies, and orders risk.
- **Coder:** implements the smallest complete change using local patterns.
- **Reviewer:** checks the actual diff and challenges correctness, scope, duplication, and failure handling.
- **Amendment Agent:** turns natural-language updates into scoped versioned proposals.
- **Technology Scout:** monitors relevant stacks and threats using trusted sources.
- **Personality Critic:** prevents over-generalisation, stale guidance, and project leakage.

## Remaining principle

This is an active foundation rather than a finished personality. It should evolve through explicit amendments, model-proposed improvements, observed deviations, and periodic technical intelligence, with meaningful changes approved by the user.
