# Current verified state

Milestones 1–5.1 are implemented. Projects are explicitly scoped and retain Active, Idle, and Off status. Pipeline runs persist loop snapshots, dependency-ordered task intelligence, planning and coding attempts, reviews, model decisions with score evidence, audit events, and durable execution claims.

The database-backed planning Worker claims Planning runs, deterministically ranks a bounded read-only repository snapshot by feature relevance, manifests, architecture/test locations, and stable ordinal path, and sends bounded safe file excerpts plus explicit `allowedRepositoryEvidencePaths` to `planner-v2`. Evidence is exact and optional: safe slash/leading-`./` variants canonicalize to snapshot paths, while directories, globs, inferred names, and fuzzy matches are rejected. A targeted correction attempt receives bounded exact errors, allowed paths, and the previous plan. Final-attempt unsupported evidence may be discarded only when the rest of the plan is valid; a warning and audit event are persisted, fabricated evidence is not, and structural errors remain blocking. Valid dependency DAGs receive deterministic conflict-aware topological ordering and atomic task plus `ReadyForExecution` persistence. Ambiguous requests enter `WaitingForClarification` without tasks; `planner-v1` remains supported for historical records.

From `ReadyForExecution`, the API previews Coder and Reviewer routing for every pending task and validates optional task-level model overrides. Routing uses rich repository/task profiles, role-specific compatibility, a versioned capability catalog, transparent score components and ranked alternatives. Reviewer diversity is a configurable preference, never a compatibility bypass. Explicit execution moves the run to `Executing`. A dedicated execution Worker claims one task at a time, prepares an isolated clone, composes earlier approved patches without commits, runs the provider-neutral Coder tool loop, stores the real task patch, and passes that patch to the Reviewer. Feedback creates a bounded revision attempt.

Coder execution now preserves the complete useful repository conversation and permits safe tools in repository-driven order. Historical tokens and provider requests are telemetry rather than spend enforcement. Technical context/output limits come from discovered model metadata with generous configured defaults, while a 30-provider-round/150-tool emergency circuit breaker keeps runaway execution finite. Retry Task remains governed by task state, dependencies, cancellation, and infrastructure invariants rather than historical token usage.

Repository commands run with an explicit sanitized environment. Windows receives required core variables including `SystemRoot`; proxy and certificate variables are copied only from a documented allowlist. Worker startup and `/api/execution/readiness` validate Git startup/version and workspace writability without a remote clone. Workspace preparation failures are safely classified and transient clone failures retry up to three times. A machine-level failure moves the run to `WaitingForInfrastructure`, preserves approved and pending tasks, removes the unconsumed attempt, and can be resumed through the project-scoped execution retry operation.

When every task is Approved or Skipped and at least one is Approved, the run reaches `ReadyForDelivery` and the loop stage becomes Committing. Eligible approved tasks are prepared as isolated local branches and validated single-parent commits, pushed with remote-ref conflict detection and lost-response recovery, then opened as focused draft pull requests through the official GitHub MCP server. A dedicated worker reconciles open, merged, closed, and changed-head state without auto-merging.

The project-scoped UI displays the dependency execution plan, ordering and conflict evidence, per-task automatic model selections, score details, alternatives, task-scoped overrides, and a safe Brain decision projection. The full Brain visualisation remains deferred. `GET /api/projects/{projectId}/pipeline-runs/{runId}/intelligence` exposes structured evidence without credentials, absolute paths, or hidden reasoning.
# Capability-aware routing update

Milestone 6 now models and persists one `TaskDelivery` per approved task, validates an immutable approved-task handoff, enforces merged-dependency eligibility and deterministic patch-sensitive idempotency, and exposes safe delivery readiness through run details. The run remains `ReadyForDelivery` at `Committing` while any delivery is unresolved. Phase 5 verifies the recorded repository, PR number, head/base branches, and approved head SHA; a merge unlocks dependent delivery, a closed or changed PR blocks precisely, and all merged deliveries complete the run consistently with skipped-task semantics.

The routing core now uses catalogue `catalog-2026-07-v2`, exact provider-aware model identities, conservative unknown-model handling, task-specific quality floors, meaningful Quality/Balanced/Economy scoring, canonical Reviewer diversity, and OpenAI endpoint-aware request construction. Milestone 6 free and deterministic local acceptance pass. Controlled live acceptance is waiting for an explicitly authorized and allowlisted target plus protected official GitHub MCP credentials.

Task execution now keeps fresh isolated clones while composing only approved direct and transitive dependency patches. A composed Git index tree becomes the current task baseline, producing independent incremental artifacts and full task-replacement patches for revisions. Composition telemetry records the source SHA, dependency IDs/count, tree fingerprint, revision-patch state, and incremental file count.
# Rate-limit-aware provider calls

Provider calls now distinguish brief capacity limits from exhausted billing quota, honor bounded provider reset information, retry the exact same model request, and coordinate short in-process cooldowns before existing model fallback. Distributed cooldowns and context compaction are not implemented.
